# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A web app for a 13-month solar calendar: 13 identical 28-day months, with the year starting on the first Monday on or after the March equinox, and Gregorian dates alongside. It's a static TypeScript and Vite site, to be hosted on Cloudflare. `docs/redesign.md` holds the review of the original app, every decision taken, and the phased plan with its status. Read it before planning changes.

## Commands

```bash
npm run dev            # Vite dev server, http://localhost:5173
npm run build          # static site in dist/ (relative asset paths, base './'), then the feed Worker in dist-worker/
npm run deploy         # build, then wrangler deploy to Cloudflare (npx wrangler login once first)
npm run typecheck      # tsc for src, then tsc -p tests (tests get Node types)
npm test               # test:unit then test:e2e
npx vitest run tests/unit/core.test.ts              # one unit test file
npx playwright test --project=chromium -g "leap"    # one e2e test, one project
```

- The e2e tests always build and start their own server (`webServer` in `playwright.config.ts`: build, then `vite preview` on port 4173). They never reuse a running server, because a leftover one serves stale files.
- Port 4173 must be free when the e2e tests run.
- The e2e projects are Chromium, Firefox, WebKit and a phone, all in London time, plus Chromium in New York, Tokyo and Kiritimati. The time-zone projects guard against the original app's off-by-one-day bug.

## Architecture

- `src/core/` is pure logic with no DOM.
  - All calendar arithmetic uses integer day numbers (days since 1970-01-01, `days.ts`, Hinnant's algorithms). Never do date maths with `Date` objects; they only read "now" and format times.
  - `astro.ts` computes equinox and solstice instants with Meeus chapter 27 and Espenak-Meeus delta-T.
  - `solar.ts` holds the calendar rules. Month 14 (`LEAP_WEEK`) is a 7-day leap week that exists only in 371-day years. `fromSolar` throws on dates that don't exist.
  - `sky.ts` turns instants into events on the viewer's local date.
- Two kinds of date: the calendar itself uses the equinox's UTC date, so it is the same everywhere. Sky events are shown on the viewer's local date. The tests check both.
- `src/names/` is the month-name plugin system.
  - Every `packs/*.json` file is picked up by `import.meta.glob`, lazy-loaded as its own chunk, and checked by `schema.ts`. The file name must equal the `id`, and files starting with `_` are skipped.
  - The core only knows month numbers; names come from packs in the UI.
  - Pack ids appear in URLs (`?names=`), so never rename one.
  - `DEFAULT_PACK_ID` in `registry.ts` is `gregorian`.
  - There are 12 packs, each with a `kind` (`historical` or `modern`) that groups the names menu. Add new ones from `_template.json`, following `docs/name-packs.md`. `tests/unit/fonts.test.ts` reads the real font files and fails if a pack uses a letter the fonts lack: Schibsted Grotesk for `name` and the interface text, Libre Caslon for the reading text (apart from `Ǣ`, which it lacks), Andika for IPA, and Libre Caslon italic or a script font for `original`.
- Festivals: a pack's optional `festivals` each have a date rule (`src/core/festivals.ts`): an equinox or solstice, a Gregorian `MM-DD` with an optional weekday, a solar date, Easter, a one-off date, or a Julian, Coptic or Persian date (`src/core/calendars.ts`), with optional `before` (weekday), `offset` and `days`. Festivals can also have `from`, `until` and `moves`.
  - `src/names/festivals.ts` turns any `FestivalSource` (a pack or a holiday set) into `FestivalDay`s, including substitute days off.
  - The festivals shown come from the chosen names, any other packs ticked in the Festivals menu (`localStorage.festivals`, a comma list; unset means every pack, `""` none), and any of the public holiday sets (`localStorage.holidays`, a comma list; `""` is none, and unset means all of them). `festivalsFrom` shows a holiday that several sets share on the same day once, with every set in `regions`; `sourceTitle` names a country whose sets all keep it ("UK, Ireland and US").
  - They show as a star (or a flag for a day off) in the grid, a dot in the year table, in the day panel, the list under the month, the table under the year, the meaning dialog (with the next date) and the ICS feed (`&festivals=…&holidays=…`).
- Public holidays: `src/holidays/*.json`, bundled with the app: the three UK regions' bank holidays, Ireland's public holidays and US federal holidays. Each set has a `country` and `dayOffName`, and optionally a `weekendRule` (the US moves Saturday's holiday to Friday) and `substituteLabel` ("observed"). `docs/name-packs.md` has the format and what's left out. `tests/unit/holidays.test.ts` checks them against GOV.UK's, OPM's and Nager.Date's lists in `tests/fixtures/`. `npm run holidays:check` refreshes those lists, and `.github/workflows/holidays.yml` does so weekly and opens a pull request when one changes. Its first job runs the project's code with read-only access; only the second, which runs nothing from the project, can write. It needs the repository setting "Allow GitHub Actions to create and approve pull requests".
- "Hear it": `src/ui/speech.ts` uses the browser's speech synthesis. A voice for the name's language reads it (Persian from the `original` script); otherwise an English voice reads the `say` respelling. Romanised tags such as `fa-Latn` never get a native voice. Buttons appear only where `say` exists and the browser can speak.
- `src/sky/moon.ts` dynamically imports astronomy-engine, so its 43 KB gzipped stays out of the main bundle. It waits for `loadMoonAfter()`'s promise, which `main.ts` settles once the first view has painted with its fonts. Quarter names appear only on the day the quarter happens, matching the grid marks.
- `src/ui/`:
  - `MonthView` builds its 28 cells once and only updates labels, marks and the month colour when the month changes.
  - `YearView` is a 28-row by 13-column table (14 columns in a leap-week year). It shrinks long month names to fit rather than breaking them, and re-measures after web fonts load.
  - On screens narrower than 980px the day panel is a sheet fixed to the bottom; its Details button (`aria-expanded`) opens the rest, and Escape or tabbing away closes it.
  - `<main>` starts with `is-loading` (hidden, and the site footer after it) and `start()` removes it after the first render, so the page doesn't shift as it fills in. The first render doesn't wait for the other packs' festivals. They, and the moon library, start loading once the first view has painted with its fonts (`document.fonts.ready`, then a frame), so they don't compete with it and Lighthouse doesn't count them towards its Largest Contentful Paint; a second render adds them. Add to calendar fills in its links again when they arrive, and the year download waits for them, so an early click still gets every festival.
  - `main.ts` holds state (selected day number, view, pack) and keeps the URL in step (`?date=YYYY-MM-DD&names=…&view=year`).
- Legal pages: `privacy.html`, `terms.html` and `disclaimer.html` are plain pages, built with the calendar (`build.rollupOptions.input` in `vite.config.mts`) and served at `/privacy`, `/terms` and `/disclaimer`. Each loads only `src/styles.ts`, the fonts and stylesheet shared with the calendar, so the calendar keeps a single stylesheet. Every page has the design kit's masthead (the "Tom Gould." wordmark, always linking to https://www.dealmobile.co.uk/, then "Solar Calendar", the page's own pills and the theme switch) and the same `.site-footer`: links to the three pages, the GitHub repo, the project's page on www.dealmobile.co.uk and the site itself. It's personal work, not a company's. The privacy policy describes what the site really does (local storage only, location only on request, Cloudflare hosting, Worker logs and Web Analytics, online speech voices), so update it when that changes, along with its date. The site is run by Deal Mobile; the contact is GitHub issues; the terms are under the law of England and Wales.
- Styles are built on the design kit (`/home/tg/BrightSites/www/dealmobile-design-kit`, the look of www.dealmobile.co.uk), installed in `public/kit/` with the kit's `tools/install.sh public/kit`. Re-run that to update it; don't edit `public/kit/` by hand.
  - `src/styles.ts` bundles the kit's `tokens.css`, `base.css` and `kit.css` from `public/kit/css/`, then the fonts, then `src/styles/app.css`, so each page still has one stylesheet. The kit's fonts in its CSS are bundled into `assets/` too; the copies under `dist/kit/` go unused, and the precache leaves them out (`globIgnores` in `vite.config.mts`). Only `kit/js/theme-switch.js` is loaded from `kit/`.
  - `app.css` uses the kit's tokens (`--page`, `--ink`, `--muted`, `--rule`, `--sun`, `--button-fill`, …) and never a raw colour, apart from the month hues, the shadows and backdrop, and the print block. The kit redefines its tokens for the dark theme; `app.css` follows the same pattern for its own (`--hue-l`, `--hue-c`, `--on-hue`, `--shadow-pop`): under `prefers-color-scheme` (guarded by `:not([data-theme='light'])`) and under `[data-theme='dark']`.
  - The one accent is the kit's vermilion: the Add to calendar and Use my location buttons, the year in the month's title (Libre Caslon italic, the kit's "voice"), and today, which is the sun: its numeral on a `--button-fill` disc in the grid, a filled cell in the year table, the Today badge, and an underline under today's month in the strip. The selected day is an ink ring on its month's tint.
  - Month colours come from the `.hue-1` to `.hue-14` classes in `app.css`, applied with `hueClass()`: 13 OKLCH hues at equal lightness and chroma, plus grey for the leap week. Text is never set in a month hue.
  - The typefaces are the kit's, self-hosted: Schibsted Grotesk (variable) for the interface, numerals and month names (the body face, since the calendar is mostly apparatus), and Libre Caslon Text for reading: the line at the top, glosses, meanings, the notes under the calendar and the legal pages. The kit ships only their Latin files, so `src/styles/fonts.css` adds the Latin Extended files (ō, ā, š) from Fontsource under the same family names; faces declared later are tried first. Andika is kept only for IPA (`--font-ipa`), with Noto Sans for Greek, Vazirmatn for Persian and Noto Sans Coptic. Neither kit face has `ǣ`, so pack `name` fields use `Æ` and put the full spelling in `original`; `forDisplayFont` builds `Ǣ` from `Æ` and a combining macron.
  - While the fonts load, Schibsted Grotesk's text is set in Arial or Roboto (Liberation Sans on Linux), and Libre Caslon's in Times New Roman (Liberation Serif) or Noto Serif, each reshaped to the real font's width and line metrics by `size-adjust` and the `-override` descriptors, so the swap barely moves anything. `src/styles/fallbacks.css` is generated by `npm run fonts:fallbacks` (`scripts/font-fallbacks.mts`) from the kit's font files and the system fonts' measured metrics, and `tests/unit/font-fallbacks.test.ts` fails when it's out of date, say after a kit update. fontkit can't set a WOFF2 variable font's weight, so Schibsted Grotesk's bold metrics are a constant in the script, measured from Fontsource's static 700. Each fallback face covers only its typeface's characters, so Greek, Persian and Coptic still reach their own fonts. Chrome on Linux draws text at whole pixel sizes, so `size-adjust` lands a little off there; an e2e test holds the fonts back and keeps the layout shift under 0.1.
- No inline scripts or `style` attributes, apart from the theme script. `public/_headers` sends a strict Content-Security-Policy (`script-src 'self'; style-src 'self'`, plus the theme script's hash and Cloudflare Web Analytics' beacon host), and e2e tests run every page under the built copy. Set styles through classes or the CSSOM (`element.style`), never `style="…"` in HTML strings.
  - The theme switch is the kit's (System, Light or Dark, `public/kit/js/theme-switch.js`, loaded deferred at the end of each page), which keeps the choice in `localStorage['almanac-theme']`. The theme is applied before first paint by a one-line script in `scripts/theme.mts`, inline so the first paint waits for no request. It also moves a choice saved by the app's older theme button (`localStorage.theme`) across, once. Its Vite plugin puts it where each page has `<script data-theme-script></script>` (a new page needs that in its `<head>`, or the build fails), and writes its sha256 hash over `{{THEME_SCRIPT_HASH}}` in the built `dist/_headers`. Edit the script there and the hash follows; `tests/unit/theme.test.ts` checks that the policy allows exactly what lands in each page.
- Hosting: Cloudflare Workers with static assets (`wrangler.jsonc` serves `dist/`). Everything in `public/` (`_headers`, `favicon.svg`, the icons) is copied to `dist/`, unchanged apart from the theme script's hash in `_headers`. `.github/workflows/ci.yml` runs the type check, unit tests and e2e tests on every push and pull request.
  - Live at https://solar.dealmobile.co.uk, a custom domain set up in the Cloudflare dashboard rather than in `wrangler.jsonc`. https://solar-calendar.solar-calendar.workers.dev still works and must stay on, because calendar subscriptions use its feed URL. Workers Builds (connected in the Cloudflare dashboard) deploys `main` on every merge, and builds a preview of other branches with `wrangler preview`, which needs the empty `previews` block in `wrangler.jsonc`.
  - `observability` in `wrangler.jsonc` keeps the feed Worker's logs in the dashboard.
  - Cloudflare Web Analytics (no cookies): `scripts/beacon.mts` is a Vite plugin that adds the beacon before `</body>` on every built page, only when `CF_BEACON_TOKEN` is set (`npm run deploy` sets it) or Workers Builds is building `main` (`WORKERS_CI=1`, `WORKERS_CI_BRANCH=main`). Dev, `vite preview`, the tests and branch previews never load it. The dashboard's automatic injection must stay off, or visits count twice. The CSP allows `static.cloudflareinsights.com` and `cloudflareinsights.com` for it.
  - `index.html` has Open Graph tags for link previews. Their image, `public/social.png`, is the kit's share card: `node /home/tg/BrightSites/www/dealmobile-design-kit/tools/render-card.js "Solar Calendar" "13 months of 28 days, each starting on a Monday, from the spring equinox." public/social.png`.
  - Search engines: `index.html` has a JSON-LD block (a `WebApplication`, a `WebSite` and a minimal `Person` whose `@id`, `https://www.dealmobile.co.uk/#person`, matches www's). It's a data block, never run, so the CSP needn't allow it, and `tests/unit/theme.test.ts` ignores it. Never add location fields. `scripts/sitemap.mts` writes `dist/sitemap.xml` at build time from each page's canonical link, dated by a legal page's "Last updated" line or, for the calendar, the latest commit; `public/robots.txt` names it, so a new page goes in `pages` in `vite.config.mts` and needs a canonical link. The static `<title>` stays while today's month is on screen; other days and the year view get a dated title.
  - Only the heading of the view on screen is an `h1`: `render()` swaps `#month-title` and `#year-title` between `h1` and `h2`, keeping their attributes and children. Style them by class, never by tag.
  - Dependabot (`.github/dependabot.yml`) opens weekly pull requests for npm packages and GitHub Actions. The workflows pin actions to commit SHAs with a version comment, and Dependabot updates both.
  - GitHub Pages is switched off for the repo; the old app used it.
- History: changing view, year or month pushes a history entry; days within a month replace it. The `popstate` handler re-reads the URL.
- Calendar feed: `src/feed/ics.ts` builds RFC 5545 text (CRLF, 75-octet folding, escaping), and the unit tests parse it with ical.js.
  - `src/worker.ts` serves `/feed.ics` and `/today.svg` (a badge with today's solar date, `src/feed/badge.ts`, in UTC or `?tz=`) and bundles every pack with an eager `import.meta.glob`. It is built by `vite.worker.config.mts`, because wrangler's bundler can't do the glob.
  - `wrangler.jsonc` routes only those two paths to it (`run_worker_first`).
  - The dev server (source) and the preview server (built bundle) both answer them through a plugin in `vite.config.mts`, so the e2e tests cover the real Worker.
- Sun: `src/sky/sun.ts` uses astronomy-engine's `SearchRiseSet` for the place's own day, in the place's time zone from `@photostructure/tz-lookup` (lazy-loaded), and handles polar day and night. The place lives in `localStorage.location`, either from geolocation rounded to 2 decimals or typed in. On a first visit, `#location-notice` explains why and offers "Use my location" (the only thing that triggers the browser's permission prompt) or "No thanks"; declining, a blocked prompt or forgetting the place sets `localStorage.locationPrompt` to `declined`, so it isn't shown again. `_headers` allows `geolocation=(self)`.
- Lazy loads: every lazy load (packs, the moon, the sun) has a `.catch` that shows a message, so a failed import never surfaces as an unhandled rejection.
- Offline: `vite-plugin-pwa` precaches the app, all packs, astronomy-engine and the Latin-script fonts.
  - It uses `clientsClaim`, so the first visit already works offline.
  - Registration is the external, deferred `public/registerSW.js`, loaded by each page (`injectRegister: false`), so the CSP holds and it doesn't block the first paint. It catches a registration cut short by leaving the page, which WebKit otherwise reports as an error.
  - The PWA and touch icons in `public/icons/` are rendered from `public/favicon.svg` (13 rays round a vermilion sun on the kit's ink) by `node scripts/render-icons.mjs`. `/today.svg` uses the kit's ink and paper and the month hues.
  - The CSP e2e test blocks service workers. Otherwise they answer requests before `page.route` can add the policy.
- Converter: `src/ui/goto.ts` shows the selected day in both forms. It only skips the field being typed in.
- Printing: prints whichever view is on screen, on one A4 landscape page. The print block in `app.css` forces light tokens using a selector that matches the dark rules' specificity. The e2e test generates a PDF in Chromium and checks that it has exactly one page; if you change month or year layout, keep that test passing.
